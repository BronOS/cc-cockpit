# Rooms: messages and shared docs between Claude tabs

External review: sol / high

## Overview
- A core communication layer for Claude tabs (design `docs/design-rooms.md`, revision 2, the source of truth): a plugin
  puts tabs in a room; members message each other and share docs through `ccc room`; main sets every identity and
  enforces every rule. Plus the per-plugin caps on tabs and texts as the person's setting.
- Replaces the team experiment's plugin-side mailbox files, background waiter and run-dir doc layer
  (`~/Projects/team-experiment`, `bronos.team`); that plugin is rebuilt on `ctx.rooms` after this, outside the app.
- Pull model: hooks and the send gate carry only a fixed pointer; room text enters a session only through that
  session's own `ccc room read`, fenced with a nonce. A typed tab gets nothing without the person's mark.
- Work stays in the worktree `.claude/worktrees/groups` (branch `feat/rooms`, based on `integration/editor-split`, the
  release branch). Another session works on that branch: merge it in when a task needs its newer code, never push to it.

## Solution Overview
- `src/main/rooms/`: `room-log.ts` (append-only, capped), `room-names.ts` (name, reserved names, title, path-part
  characters, room id shape; shared by registry, docs and the saved tab record, so it lives in `src/shared/` since Task 4), `room-registry.ts` (rooms, members, invites, queues, pause; persisted),
  `room-docs.ts` (the doc store and its access rules), `room-delivery.ts` (pointer by gate, held, draft bit, mark, caps),
  `room-stop.ts` (the Stop decision, block caps, auto-pause), `room-fence.ts` (the `read` output), `room-service.ts`
  (wires them to the session registry, the send gate, the tab manager, the socket handlers and HostApi).
- Delivery never uses the send gate's queue for room text: the gate gets one pointer item only when `maySend` and the
  tab qualifies; a takeover returns the room's messages to held. A Stop answered with a block is reduced to `working`
  and does not deliver the gate's head.
- Membership and the mark live in the tab record (restored tabs get new ids); restored members count as typed and rooms
  restore paused.
- `ctx.rooms` in the plugin host forwards to main (no host-local state: rooms span the tabs main owns).
- Caps: `main/plugins/plugin-limits.ts` (defaults, ceilings, overrides in `app.json` through `settings-service.ts`) read
  through a `limits(pluginId)` getter by HostApi and the room delivery; written only by the shell page and the
  shell-only `ccc plugin limits` write.

## Technical Details
- Room record (`<data>/rooms/<id>/room.json`): `{ id, pluginId, projectId, title, createdAt, endedAt?, paused,
  members: { [name]: { coordinator } }, queues: { [name]: Message[] } }`; `Message` = `{ id, from, text, at }`.
  Room id: `randomUUID`. Name: `^[a-z][a-z0-9-]{0,30}$`, reserved `all`, `plugin`, `person`, `user`, `system`.
  Title: 1-60 characters, no control, quote, bracket or bidi characters.
- Tab record gains `room?: { id, name, coordinator, mark }`; membership is matched by room id and name, never tab id.
- Invite: `{ code (random, 128-bit base32), roomId, name, coordinator, expiresAt }`, in memory, single use, 10 minutes.
- Pointer text (fixed): `N room message(s) waiting: run ccc room read`. Stop hook output: `{"decision":"block",
  "reason":"<pointer>"}`. The Stop hook request carries `stop_hook_active` and asks for a reply `{ block?: string,
  ackId? }`; `ccc` then sends `{ cmd: 'hook.ack', token, args: { ackId } }`; a block without its ack within 2 s counts
  as a plain Stop. `hook.ack` is a hook-socket request (tab token required, only for the block main just issued), not
  host-only and not in `CORE_CLI_COMMANDS`.
- Fence per message: `[cockpit room "<title>" <nonce>] from <name> (a room member, not the person):`, body lines
  prefixed `| `, `[end <nonce>]`; nonce 16 random hex per `read`.
- Docs: `<data>/rooms/<id>/docs/{shared,members/<name>}/...`; parts `[A-Za-z0-9._-]+`, not `.` or `..`, depth at most 4;
  256 KiB per doc, 20 MiB per room; open `O_NOFOLLOW`, `fstat` on the descriptor (regular file), parent dirs created by
  main with no links; write to `<name>.tmp-<rand>` then rename.
- Log: `<data>/rooms/<id>/log.jsonl`, 20 MiB cap (drop the oldest half with a line saying so).
- Caps (defaults / ceilings): opens a minute 5 / 60, sessions sends a minute 30 / 300, room sends a minute per member
  20 / 120 and per room 60 / 600; constants: 5 rooms per plugin, 20 members per room, Stop blocks in a row per tab 5,
  auto-pause after 100 deliveries with no person input in the room. `app.json` › `pluginLimits[id]`.
- New IPC channels: `tabs.roomMark` (`adapted`), `rooms.deliverHeld` (`adapted`), `rooms.view` (`yes`: browsers may read,
  message text included, design §5), `rooms.pause` / `rooms.resume` (`adapted`), `rooms.remove` (`adapted`, an
  `ApprovalDialog` from a browser in server mode), `rooms.reveal` (`no`), `plugins.limits.get` (`yes`),
  `plugins.limits.set` (`adapted`, browsers only in server mode). `adapted` = counts from a browser only when `server`.
