## Overview
- Build **Inbox** (`bronos.inbox`), the user's daily-driver panel: the top items of every source
  plugin (Chat, Gmail, Jira; Forgejo later) in one list, re-ranked by Inbox's own configurable

## Solution Overview
- **Core (0.9.7)**: `ctx.services.useAll(name)` returns a `ServiceSet` over every enabled provider of
  the name in the project, resolved on every call, with events from every provider and a
  provider-set change event. `use` and the provider pick stay as they are. A consumer declares a
  collected service in its manifest, which also silences the Plugins page's "several providers,
  pick one" warning for that name.
- **Feed contract `inbox-feed` v1** (design "The feed contract"): `describe()`, `features()`,
  `items({limit})`, `open(id)`, optional `markRead(id)`, event `changed`. Items carry `rev` for
  "done until it changes". Answers come from the provider's cache, never an API call.
- **Calendar contract `calendar` v1** (design): `day`, `upcoming`, `respond`, `open`, event `changed`.
- **Inbox**: validates and caps every feed answer, ranks with
  `level + weight + boosts − age`, dedupes Jira mail, keeps done / snooze in `ctx.appStorage`, draws
  the mock-up's panel. Its settings (sources keyed by provider plugin id, levels, boosts, calendar
  position, done/snooze times, badge) live in the panel's own settings view and app storage, since
  the sources are dynamic and a manifest settings schema is static.

## Technical Details
- `ServiceSet`: `providers()` → `{ pluginId, title, handle }[]` (handle bound to that one provider,
  whatever the pick; plugin-title order); `on(event, (data, pluginId) => …)` → disposer;
  `onChange(listener)` → disposer. Same rules as `use`: plain data (`cloneData`), fresh errors,
  cycle detection, `caller()`, a stale handle after a provider reload fails as `use` handles do.
- Manifest declaration of a collected service: **`services.collects: ["inbox-feed"]`**, a list of
  names that must also be in `services.uses` (subset check). `services` is strict
  (`additionalProperties: false`, `src/shared/manifest.ts`), so an older app refuses Inbox's
  manifest: Inbox needs 0.9.7, stated in its README and marketplace description (there is no
  min-app field). The source plugins do not use the key, so older apps keep loading them.
  `useAll` refuses a name not in `collects`.
- Feed caps (Inbox side): ≤ 50 items a call; title 300, from/where 120, label 24, badge 6 chars;
  `color` one of `green red blue amber violet grey`; `level` one of `urgent action fyi noise`;
  unknown fields dropped; numbers finite; everything rendered as text.
- Ranking defaults: levels 300 / 150 / 50, noise hidden; weights by `kind` chat 30, mail 15,
  issues 0, other 0; unread +10, direct or mention +20, due within 2 days +25, age −5 an hour at
  most −40; ties newer first. A snoozed item coming back: +500 for the rest of the day or until
  opened or done.
- Done / snooze state: app storage key per item `<pluginId>:<id>` → `{ kind, rev, at, until? }`,
  dropped 14 days after last seen. Done hides while `rev` matches. Snooze until: 1 h, afternoon
  (14:00), tomorrow morning (9:00), until it changes.
- Refresh: re-read a source on its `changed` (debounced 1 s), all sources every 60 s, and when the
  provider set changes (`onChange`).
