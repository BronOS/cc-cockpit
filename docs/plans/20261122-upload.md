# Uploads from the person's device

External review: sol / high

## Overview
- Put files from the device the person is at onto the cockpit machine (design `docs/design-upload.md` revision 2, the source
  of truth; it mirrors `docs/design-download.md`): a browser view, server mode's browsers and the desktop's remote window.
  The local desktop page gets nothing (remote only, as Download).
- Two ways in: the Files panel (cockpit.files: "Upload here…" on a folder row and the project folder, and a drop from Finder
  onto a folder or file row) and a terminal tab (Claude or shell: a drop, or a paste whose clipboard holds files and no
  text), which opens core's folder chooser and ends with the uploaded paths pasted into that tab.
- Several files per upload, no folders; 2 GiB per file, 100 files, the server's free disk checked first. A name clash asks
  Replace / Keep both / Cancel in an armed `ApprovalDialog`.
- One core flow: the panel SDK (`ccPanel.upload.pick` / `files`) posts `File` objects to the shell, the shell asks main over
  its own socket (`uploads.begin`), main checks view, role and folder and mints per-file tokens, and the shell sends
  sequential `fetch` PUTs of slices to `/u/<token>?offset=<n>` behind the full cookie-and-key check, the slice size adapting
  between 256 KiB and 8 MiB to stay inside the gateway's 30 s request bound (design §3.3). Never XHR.
- Who: the owner and write guests; read guests never.

## Development Approach
- **testing approach**: Regular (code first, then tests); every task ends with its tests, all passing before the next.
- main is the authority: the view, its device and its role come from the connection main bound (`whoOf`, `isOwner`,
  `GuestStore.access` read live), never from the payload; a panel key is resolved through that view's layout; every folder is

## Solution Overview
- `main/files/uploads.ts` owns uploads: begin (folder, names, clashes, caps, limits), resolve, cancel, tokens, the paste
  rule and the folder listing; `main/files/upload-writer.ts` owns the bytes on disk (temps, offset writes, commit, the temps
  record). The gateway only routes `/u/` to it and tells it about revokes, disconnects, None exit, guest ends and stop.
- A Files upload: the panel page picks or takes a drop inside its own frame → `cc-plugin.upload` to the shell → the shell
  (panel frames only) sends `uploads.begin {source: {panel}}` → clashes go to core's armed dialog → tokens → chunked PUTs →
  progress and result notices.
- A terminal upload: the shell catches a drop or a file-only paste on a Claude or shell tab → core's folder chooser (listing
  through `uploads.folders {tab}`) → the same begin, dialog and PUTs → `uploads.paste` → main answers the text or `held` →
  the shell pastes with xterm's own `paste` (the person's input path, `typed`).

## Technical Details
- `src/shared/uploads.ts`: `UPLOAD_MAX_FILE_BYTES` 2 GiB, `UPLOAD_MAX_FILES` 100, `UPLOAD_CHUNK_MIN_BYTES` 256 KiB,
  `UPLOAD_CHUNK_START_BYTES` 1 MiB, `UPLOAD_CHUNK_MAX_BYTES` 8 MiB (the client doubles under 2.5 s a chunk, halves over 10 s
  or when the 30 s request bound cut it),
  `UPLOAD_FREE_MARGIN_BYTES` 1 GiB, `UPLOAD_IDLE_MS` 60 s, `UPLOAD_MAX_PER_DEVICE` 2, `UPLOAD_MAX_APP` 6, begins 20 per
  10 min per device, `UPLOAD_FOLDER_LIST_MAX` 500, keep-both numbering up to 99; the name rule (`checkName`'s rules plus no
  control, bidi or invisible format characters (`HIDDEN_TEXT`) and no lone surrogates), the pasted name (`pasted-YYYYMMDD-HHMMSS.<ext>` from the device clock
  and the type: `png`, `jpg`, `gif`, `webp`, `pdf`, else `bin`), the in-upload dedupe,
  the `.git` rule (named and real path, case-insensitive on darwin), the paste escape (backslash before
  `` \ ' " ` $ & * ( ) [ ] { } ; | < > ? ! # ~ `` and ASCII space only, every non-ASCII character kept, U+202F
  included; space-separated, one trailing space; `null`, so the paste is held, when a path holds a control, bidi or
  invisible character or a lone surrogate); Keep both numbering is `numberedUploadName` (`shared/uploads.ts`: `numberedName`
  from `src/shared/numbered-name.ts`, `null` past 99 or past the 255-byte name limit, so the file is refused with a reason).
- Payloads: `uploads.begin {source: {panel: key} | {tab: id}, folder, files: [{name, size, pasted?}]}` →
  `{uploadId, refused: [{index, reason}], clashes: [{index, name, replaceable}], tokens?: [{index, token, name}]}` or a
  refusal; `uploads.resolve {uploadId, choice: 'replace' | 'keep-both' | 'cancel'}` → `{tokens}`; `uploads.cancel
  {uploadId}`; `uploads.paste {uploadId, manual?}` → `{text} | {held: reason, text}` (automatic at most once per upload;
  `manual: true` is the held notice's Paste path, any number of times); `uploads.folders {tab, path}` → `{folders: string[],
  more}`.
- Token: 32 random bytes base64url, in memory, bound to `{deviceId, windowId, uploadId, index, folderReal, name, choice,
  size}`; multi-use (one PUT per chunk at the right offset); the idle clock is per upload, reset by body bytes read.
- `/u/` answers: `200 {received}` per chunk, the last `200 {done: true, name, path}`; 400, 409 `{expected}`, 413, 507; a guest's
  refusal 404; `Cache-Control: no-store`, `X-Content-Type-Options: nosniff`.
- Writer: temp `.cc-upload-<16 hex>` in the target folder, `O_CREAT | O_EXCL | O_NOFOLLOW | O_WRONLY`, `0644`; commit by
  `fs.link` (exclusive, numbered on `EEXIST`) then unlink, or `copyFile(COPYFILE_EXCL)` on `EPERM`, `ENOTSUP`, `EOPNOTSUPP`,
  `ENOSYS`, `EXDEV`; Replace by `rename` after an `lstat` (regular file only), with the old mode minus setuid, setgid and
  sticky; the record `<data>/uploads/temps.json`.
